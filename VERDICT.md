# My Verdict

## What I would keep

I tried both approaches: going **full auto mode with Claude Cowork** and going **step by step with Claude Code in Visual Studio Code**.

While Claude Cowork arrived at very similar conclusions, I came away with only a shallow understanding of the case. Discussing it in more detail with Claude Code made me dig deeper, and I can defend the results better.

- **Take the slower road.** The step-by-step approach builds real understanding.
- **Keep the independent reviewer agent.** Using one was Claude's idea, and I would definitely keep it.

## Where Claude went wrong

- **Too much back-and-forth on the reminder mail.** There were long discussions on how to send it. Next time I would frame my lean ideas upfront.
- **Lack of focus.** I would make Claude focus on the one main idea to test. It added a Turkish translation, which is a good idea, but not the first priority.
- **Cumbersome first test ideas.** Adding a date to the report and calling customers to ask whether they remember it is hard to do *and* doesn't test the right metric.

## What I would change in the setup next time

- **No re-runnable setup for this kind of work.** In real life, this type of product work usually doesn't repeat, and doing all of it via Claude clouds my thinking, agency and judgement.
- **Use Claude where it shines.** I would use Claude for data analysis and summaries, but check much more with stakeholders before building a prototype or making assumptions, at least in cases like this one, where the general ideas (e.g. *send a reminder e-mail*) are easy to discuss.
- **Prototype vs. spec depends on complexity.** In more complex cases, I would build the prototype as a spec. In the current case, I would ask the devs whether they'd prefer a prototype alongside the spec.
